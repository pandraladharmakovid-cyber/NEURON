# Accessibility
Semantic landmarks, labelled controls, visible feedback and keyboard navigation are used. Chromium axe serious/critical scans cover projects, CSV, settings, media, custom and peer routes. A small-viewport test checks document-level overflow; it is not a full assistive-technology certification.

Manual release checklist: tab through import/train/predict/export and dialogs, inspect visible focus, verify error text is readable at 200% zoom, use a screen reader on status updates, and check dark-theme contrast. Native file, device permission and browser save dialogs remain browser/OS controlled. Charts should be interpreted alongside numerical metrics. Report inaccessible workflows with browser, OS, route and reproduction steps; do not attach private datasets to public issues.
